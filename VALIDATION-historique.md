# Vérifications — KiloM 1.1.9

Version 1.1.9 : 100 contrôles DOM réussis avec pont Android simulé. Nouveaux scénarios : sortie nouvellement créée active malgré une date antérieure, restauration de la sélection, choix Waze/Google enregistré, URL officielle et prochaine école/retour corrects, exclusion des identifiants personnels, classement À faire/Terminées, section vide, annulation et reprise, absence de navigation après fin, choix manuel conservé et échec de sauvegarde sans changement de sélection. Données des sorties inchangées par les actions de navigation. Compilation Android 1.1.9 code 14, signature v2/v3 et même certificat que 1.1.8 validés. Ressources embarquées vérifiées; moteur, distances et modèle Excel identiques octet pour octet à 1.1.8. Pas d’essai sur téléphone réel : lancement des applications installées et repli navigateur restent à vérifier sur appareil. Pas de rendu visuel Chromium réalisé pour cette version.

Version 1.1.8 : confirmation finale utilisateur de 6,5 km dans les deux sens pour Admin ↔ Dôme. Vérification des 2 209 entrées contre la grille affichée, avec une seule correction explicite; comparaison à 1.1.7 : seule la cellule Dôme → Admin passe de 7,4 à 6,5. 165 assertions moteur/modèle, 76 contrôles DOM et 61 contrôles d’optimisation réussis. Régression ciblée dans les deux sens : 13 km; export F12 = Aller/retour, J12 = 6,5, K12 = 8,45, N48 = 8,45; formule originale conservée. Compilation Android 1.1.8 code 13 et signature v2/v3 validées, même certificat que 1.1.7; modèle et matrice embarqués contrôlés. Pas d’essai sur téléphone réel ou dans Microsoft Excel.

Règle Excel aller-retour simple, signatures, dates ISO, format numérique I19 et composants natifs du modèle préservés. Empreinte des exports automatiques actualisée pour tenir compte de la nouvelle règle de distance. Compilation Android 1.1.7 code 12, signature v2/v3 et même certificat que 1.1.6 vérifiés. Vérifications initiales et limites conservées :

- Compilation Java puis DEX pour Android API 26 minimum, ressources API 35.
- Vérification de la signature APK v2 et v3, un seul signataire.
- 142 assertions du moteur : distances directionnelles, aller-retour simple, minimum par sortie, circuit de plusieurs écoles, détour unique, covoiturage, mercredi de remise, changements de période, changement d’heure, pagination sans couper une sortie, XML, formules, montants mis en cache et champs du profil.
- Conservation octet pour octet des composants du modèle autres que la feuille Form FD et les paramètres de recalcul du classeur.
- Importation du fichier produit dans un deuxième moteur de feuille de calcul : total recalculé 17,983686 $, identique au moteur KiloM pour le jeu d’essai.
- Inspection visuelle du rendu du fichier produit. Le rendu secondaire ne prend pas en charge l’affichage du logo TIFF; l’image d’origine reste présente et identique dans le XLSX.
- 29 vérifications d’interactions DOM : premier lancement, profil, conservation des zéros dans les identifiants, calcul affiché, création/modification/suppression de sorties, réorganisation des étapes, validation de détour, calendrier, rendu de l’historique et des exports, échappement du texte.

Limites des essais : le pont Android est simulé dans les essais DOM. Le lancement de Chromium a été bloqué par les restrictions système de l’environnement; aucun contrôle visuel complet de l’interface Android n’est revendiqué. Aucun appareil ou émulateur Android n’était disponible. Les notifications, alarmes, installation, sélecteur de fichiers, ouverture dans Excel et partage entre applications nécessitent un essai sur téléphone.

Les fichiers de test contiennent un profil fictif et ne sont pas livrés comme une réclamation réelle. La suite Chromium est fournie pour être exécutée dans un environnement qui le permet; elle n’a pas été déclarée réussie.
